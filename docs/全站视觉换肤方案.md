# 全站视觉换肤方案（绿色 → 暖陶土 / 暖米白 + 衬线标题）

> 状态：**已实施并验证**。本文件既是方案也是变更记录。

## 一、需求

1. 全站绿主色（应用编辑页那套 `#00b894`）改为 `#DA7757`
2. 页面底色改为 `#FAF9F6`
3. 字体采用 Anthropic 的 Copernicus 风格
4. 追加：管理页面不需要改（用户看不到后台）

## 二、字体决策（唯一需要取舍的地方）

**Copernicus 拿不到**：它是 Anthropic 的私有字体，`https://www.anthropic.com/fonts/Copernicus-Book.woff2`
返回 404，无公开 CDN，也没有再分发授权。因此不能引入。

**结论**：用观感最接近的暖衬线系统字体栈，不加载任何 webfont：

```
'New York', 'Iowan Old Style', Georgia, 'Songti SC', 'Source Han Serif SC', 'Noto Serif SC', 'Times New Roman', serif
```

- macOS 命中 **Apple New York**（Iowan Old Style 的直系后代，暖衬线观感与 Copernicus 最接近）
- Windows / Linux 回退 Georgia
- 中文回退宋体系（Songti SC / 思源宋体）

**为什么不用免费 webfont**（Fraunces / Source Serif 4 都试过可达）：引入外部字体意味着
网络依赖、部署体积增加、`font-display` 闪字，而收益有限。系统栈零成本且不闪字。

> 若日后要换成真 Copernicus 或某个 webfont：把字体文件放进 `public/fonts/`，
> 在 `tokens.css` 里加 `@font-face` 并把字体名插到 `--font-serif` 最前面即可，其余代码不用动。

## 三、改动范围

### 1. 新增令牌层（唯一真值源）

| 文件 | 作用 |
|---|---|
| `src/config/theme.ts` | 颜色 / 字体令牌 + `antdTheme`（ConfigProvider 配置）+ `TagMeta`/`tagStyle` |
| `src/styles/tokens.css` | `:root` 上的 `--color-*` / `--font-*`，与上者逐项镜像 |

两处必须同步修改。组件样式一律写 `var(--color-*)`，不再写字面色值。
`App.vue` 用 `<ConfigProvider :theme="antdTheme">` 包住全站；
`main.ts` 里 `tokens.css` 必须排在 `base.css` 之前（base 消费这些变量）。

### 2. 主色

`#00b894` → `#DA7757`，共 16 处：`styles/chat.css`、`Chat/ChatBoard.vue`、
`Chat/MessageRow.vue`、`MyAppCard.vue`、`FeaturedAppCard.vue`。

`ChatBoard` 里 `--glow-rgb`（开关切换脉冲的 box-shadow 光晕）必须是 **R, G, B 纯数字**，
不能写 `var(--color-primary)`（那是 `#hex`，进不了 `rgba()`）。因此令牌层另给了
`--color-primary-rgb: 218, 119, 87`。

### 3. 底色

- `body` → `--color-page-bg` `#FAF9F6`
- 内容区 `.basic-layout__content` → 同上（同时 `colorBgLayout` 覆盖 antd 的 `#f5f5f5`）
- 卡片 / 表格 / 弹窗保持纯白 `#FFFFFF`，与米白底形成层次
- **表头**：antd 的表头不是白也不是绿，而是 `colorFillAlter`（默认 `#fafafa` 冷灰）。
  查 `node_modules/ant-design-vue/es/table/style/index.js:229` 起，`tableHeaderBg` /
  `tableRowHoverBg` / `tableBodySortBg` / `tableFooterBg` **全部指向这一个 token**，
  所以在全局把它设为 `--color-surface-subtle` `#F4F2ED` 一次即可全暖。
- 名称列渐隐遮罩（`.name-cell--overflow::after`）的 `#fff` 改成
  `--color-surface-fade-from` / `--color-surface-fade-to`，换底色时自动跟随。

### 4. 冷灰清理

46 处 `rgba(0, 0, 0, x)` 文字色换成 `--color-text*`（暖墨 `rgba(20,20,19,x)`），
避免冷灰在米白底上发蓝。仅替换 color / border-color / fill / stroke 属性，
`box-shadow`、遮罩、`background` 不动。

### 5. 标签色板

antd 预设色名（`red` / `blue` / `yellow`）是冷色高饱和色板，摆在暖底上会打架。
改成「字色 + 底色 + 描边」三件套，与主色同源：

| 应用标签 | 配色 | 依据 |
|---|---|---|
| 工具 | 陶土 `#c05f41` / `#fbf0eb` | 品牌主色系 |
| 网页 | 暖中性 `#57534e` / `#f4f2ed` | 不抢焦点 |
| 个人主页 | 琥珀金 `#d48806` / `#fffbe6` | 唯一保留的第三强调色 |

| 用户角色 | 配色 |
|---|---|
| 管理员 | 陶土 `#c05f41` / `#fbf0eb` |
| 用户 | 暖中性 `#57534e` / `#f4f2ed` |

三件套必须用 `:style` 而不是 `:color`（antd 的 `color` prop 只认预设色名或单色）。
`tagStyle()` 收敛在 `config/theme.ts`，表格列 / 下拉选项 / 详情弹窗三处共用。

### 6. 字体作用域

衬线只作用于**标题层级**，正文 / 表格 / 表单保持无衬线：

- 前台：`.hero-title`（首页大标题）、`我的应用` / `精选应用`（`<h2>`）、
  登录页 `NO CODE & NO PAPER`、注册页 `REGISTER`、`a-card` 的 title
- 后台：**整段回退无衬线**

后台回退的实现要点（踩过的坑）：

1. antd 的 Modal 默认 **teleport 到 `document.body`**，所以只给页面根节点加
   `.admin-scope` 是**够不到弹窗的**（实测弹窗标题仍是 New York）。
   解决办法是给两个后台弹窗加 `wrap-class-name="admin-scope"`
   —— 该 class 落在 `.ant-modal-wrap`，是 `.ant-modal-title` 的祖先。
2. antd 样式运行时注入到 `<head>` 末尾，`base.css` 在产物里排在它前面；
   同优先级下后注入的赢，所以后台回退那条规则需要 `!important`。

### 应用编辑页 header 应用名加截断（追加需求）

与后台表格、应用详情卡片同一套实现：`.name-cell` 系列样式 + `useNameTruncation` 判定。

两点差异需要说明：

1. **测量容器**：该页没有 `a-table`，把应用名所在的 `.app-info-main` 当容器。
   它是 `flex:1 + min-width:0`，自身不变宽，真正随窗口变的是外层网格列；
   容器变宽被 ResizeObserver 捕获后重新判定，间接覆盖到列宽变化。
2. **组合式函数放宽**：原实现只接受 `a-table` 实例（取 `$el`），且用 `onMounted` 挂
   ResizeObserver。这里容器 ref 是「首帧之后才就绪」的（`:ref` 惰性 + 数据异步），
   `onMounted` 时可能还是 `null`，**观察者根本不会挂上**。因此改为：
   - 参数类型放宽为「组件实例或普通 `HTMLElement`」，内部 `resolveEl()` 两个形态都认；
   - 挂载时机由 `onMounted` 改为 `watch(containerRef, …, { immediate: true, flush: 'post' })`，
     覆盖「ref 从 null 变成元素」这一次跳变。
   已回归验证后台两张表不受影响（见上表最后两行）。

| 前台大标题字体 | 首项 `"New York"` |
| 后台弹窗标题字体 | `-apple-system`（`inAdminScope: true`） |
| 三个标签渲染点 | 表格列 / 下拉选项 / 弹窗内，色值全部符合上表 |

验证方式：JDBC 注册并提权一个临时管理员 → 走**真实登录表单** → 真实表格 / 弹窗 /
下拉截图采样。临时账号已删除并二次核对（残留数 = 0），探针脚本已清理。

工程校验：`vue-tsc --build --force` 0 错误、`eslint src/` 0 错误 0 警告、
`npm run build` 通过。

### 名称截断改为「左对齐 + 右缘渐隐」（追加需求）

**原实现的观感问题**：渐隐遮罩一直在右缘、从来没变过，问题出在内层文字是
`left: 50% + transform: translateX(-50%)` 的**居中裁切**——文字以盒子中线对称溢出，
于是左右两端同时被切掉。视觉上就像"从中间截断"，`dsf41测试…` 连第一个字都读不到。

**改动只有一条规则**（`src/styles/base.css` 的 `.name-cell-text`）：

```diff
   position: absolute;
-  left: 50%;
-  transform: translateX(-50%);
+  left: 0;
```

**为什么这么小**：溢出判定读的是 `textEl.scrollWidth`（文字自然宽度），与文字定位方式无关；
遮罩本来就是 `inset: 0 0 0 auto` + 28px 宽，天生只在右缘。所以判定逻辑与遮罩都不用动。

三处截断（应用管理 / 用户管理的两列 / 应用编辑页 header）共用这一套，改一处全生效。
实测：

| 位置 | 左端对齐差 | 右侧超出 | 结果 |
|---|---|---|---|
| 应用管理 应用名称 | `0px` | `113px` | 从首字开始读，右缘渐隐 |
| 用户管理 用户名（两条） | `0px` | `215px` / `211px` | 同上 |
| 应用编辑页 应用名（长） | `0px` | `124px` | 同上 |
| 应用编辑页 应用名（短，73px） | `0px` | 不溢出 | **不挂** `--overflow`，完整显示 |

遮罩实测 `inset: 0px 0px 0px 112px`、宽 28px，确认只在右缘、不侵入左侧。

## 五、已知取舍与遗留

- **`priority=99` 的优先级数字**原为 `#cf1322` 正红，与新陶土主色撞色且偏冷，
  改用 `var(--color-primary)`。若要求保留红色，改回即可（`AppManagePage.vue`）。
- `MessageRow.vue` 的行内代码色 `#e83e8c` 保留：粉色在该暖调色板里可读且是代码色惯例。
- 反白文字（用户气泡、蒙版按钮上的 `#fff`）不参与换肤，属语义白。
- 应用编辑页 `部署成功` 弹窗的标题会走衬线（未加 `admin-scope`），符合"前台保留衬线"的约定；
  因该弹窗只在部署成功后出现，未做运行时实测。
- `npm run build` 仍有主 chunk > 500 kB 警告，为既有问题，与本次换肤无关。

## 1. 小图标的亚像素横向偏移：静止偏右、动画期间对齐

**现象**

聊天输入区的小图标（`send-btn` 的箭头、`prompt-tools` 三个按钮的图标）静止时横向偏右（半个像素量级），
悬停/点击**动画播放期间是对齐的**，动画一结束又偏回去 → 视觉上表现为可观测的跳变。

**已做的处置与结果**

| 处置 | 结果 |
|---|---|
| `.anticon` 加 `will-change: transform`（常驻合成层） | ✅ 有效：两态一致，实测「丝滑」。但它是**指示不是承诺**——浏览器可在内存吃紧时丢掉提升，届时偏差会偶发回来 |
| 左列网格宽度用 `round()` 取整到整像素（`AppEditPage.vue` 的 `--col-left`） | ❓ **未解决**：注释掉 `will-change` 后异常依旧。且这笔改动**是否生效本身未验证** |
| 换图标（`ArrowUpOutlined` → `CaretUpOutlined`） | ❌ 现象不变（已保留 caret） |
| 按钮从正圆改圆角矩形 | ❌ 无改善（已回退为正圆） |
| 静态亚像素补偿（`left: -0.5px` / `-1px`） | ❌ `-1px`、`-0.5px` 都过头，而 0 偏右 → 静态路径的落点是**离散**的，没有可用的补偿值 |

**已知事实（用于排除）**

- 几何上应当精确居中：flex 居中 + `1em` 正方 svg + glyph 在 `viewBox` 内留白左右各 92、上下各 88，两侧对称。
- `send-btn` 的图标盒是**整数**（`font-size: 14px`），`prompt-tools` 的是**小数**（`font-size: 10.5px`）——两者都出现，
  所以「盒子尺寸是小数」不是必要条件（但可能是其中一条来源）。

**未验证的关键一步（下次从这里开始）**

```js
const g = document.querySelector('.chat-body')
console.log('左列轨道 =', getComputedStyle(g).gridTemplateColumns.split(' ')[0])
console.log('round() 支持 =', CSS.supports('width', 'round(down, 10px, 1px)'))
```

注意用 `gridTemplateColumns`（已使用的轨道尺寸，真实 px）判断，**别**用 `--col-left`——自定义属性的 computed 值
只是变量替换后的原文，不会算成 px。

| 输出 | 含义 |
|---|---|
| 整数，如 `296px` | 取整**已生效**但异常仍在 → 「位置小数」不是（唯一）原因，模型需重做 |
| 小数，如 `295.75px` | 取整**没生效** → 先修门控/表达式，再看是否还需要 `will-change` |

**可能的下一步**

1. 跑上面那一步，先分清是「没生效」还是「生效但不够」；
2. 若确认已生效仍偏：逐个排除——换绘制原语（border 三角 / 字体字形，位置连续、不作整体吸附），
   或把图标盒尺寸整数化（`font-size` 取整）；
3. 若确认没生效：核实 `@supports (width: round(down, 10px, 1px))` 与
   `round(down, (100% - 16px) / 4, 1px)` 在目标浏览器的实际行为。

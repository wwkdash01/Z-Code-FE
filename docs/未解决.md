## 1. 小图标的亚像素横向偏移：静止偏右、动画期间对齐 —— 已解决（2026-09-13）

**现象**

聊天输入区的小图标（`send-btn` 的箭头、`prompt-tools` 三个按钮的图标）静止时横向偏右（半个像素量级），
悬停/点击**动画播放期间是对齐的**，动画一结束又偏回去 → 视觉上表现为可观测的跳变。

**根因**

图标靠 `transform` 做动画时会被提升为**独立合成层**，但只在动画**播放期间**是合成层：
动画一结束层就被回收，图标回到父层，改由父层的绘制原点取整。图标盒子的尺寸是小数
（`prompt-tools` 为 `font-size: 10.5px`），两条光栅化路径的落点因此差约半个像素
→ 正好表现为「动画期间对齐、静止偏右」。

**处置**

| 处置 | 结果 |
|---|---|
| **`.anticon` 基础值改用真值 `transform: translate3d(0, 0, 0)`，并把关键帧首尾帧的 `transform: none` 一并换掉** | ✅ **最终修法**。3D 变换是实际值、浏览器必须建层，两条路径合并；实测两态一致，且 `send-fly` 飞行动画、悬停抬起、圆形裁剪全程正常 |
| `.anticon` 加 `will-change: transform` | ⚠️ 一度有效，但它是**提示不是承诺**——浏览器内存吃紧时会撤掉提升，偏差会偶发回来。已被上面的真值取代 |
| 左列网格宽度用 `round()` 取整到整像素（`AppEditPage.vue` 的 `--col-left`） | ➖ 与本条无关：那条判定依据（「注释掉 `will-change` 后异常依旧」）本身不成立——「关掉修法 A 问题还在」只能说明 A 不充分，不能否定 A。改动保留（对网格对齐本身仍可能有用） |
| 换图标（`ArrowUpOutlined` → `CaretUpOutlined`） | ❌ 现象不变（已保留 caret） |
| 按钮从正圆改圆角矩形 | ❌ 无改善（已回退为正圆） |
| 静态亚像素补偿（`left: -0.5px` / `-1px`） | ❌ `-1px`、`-0.5px` 都过头，而 0 偏右 → 静态路径的落点是**离散**的，没有可用的补偿值 |

**关键点**

只改基础值不够：`@keyframes tool-tap` 原来的 `0% / 100% { transform: none }` 会让层在动画**首尾两帧**
被回收，偏移会在点下去那一瞬回来，必须把首尾帧也换成 3D 值。
`send-fly` 首尾本来就不是 `none`，但仍统一改成 `translate3d` 以保持全程 3D。

**相关位置**

- `src/components/Chat/ChatBoard.vue`：`.prompt-tools :deep(.ant-btn .anticon)` 与 `.send-btn :deep(.anticon)`
  的 `transform: translate3d(0, 0, 0)`；`@keyframes tool-tap` / `@keyframes send-fly` 的 3D 化
- `src/pages/app/AppEditPage.vue`：`.app-edit-page { --col-left }` 的 `round()` 取整（保留，与本条症状无关）
- `docs/chatboard-history-rerender.md` 第九节的机制描述是**对的**（「位置小数 → 父层与独立合成层两条光栅化
  路径取整不同」），本次只是把它落到了确定性的修法上，不需要更正

## 2. 撤回退场「直接消失」：渐隐在 layout 阶段就被裁光 —— 已解决（2026-09-17）

**现象**

点「撤回消息」后，两条消息（提问 + 失败气泡）**没有渐隐、也不收空间**，直接消失；`LEAVE_MS` 到点后才从队列里被移除。

**根因**

`overflow: hidden` 让 flex 项的**自动最小尺寸退化为 0**，退场的那两行因此成了容器里唯一可压缩的项，
在布局阶段就被 flex 压成 0 高，再被 `overflow: hidden` 裁掉：

1. `.chat-board-content` 是 `flex: 1 + overflow-y: auto` 的**列** flex 容器，消息总高超过容器 → free space 为负；
2. 平时行压不扁，靠的是 flex 项的 `min-height: auto`（`overflow: visible` 时它解析为内容高度）——
   这也正是聊天区会滚动、而不是被压扁的原因；
3. `.msg-row.is-leaving` 挂上 `overflow: hidden` 的那一刻，这条保护失效（自动最小尺寸 → 0）；
4. 其它行仍受保护、不可压缩，**唯一可压缩的就是正在退场的那两行** → 被压到 0 高。
   这一切与 class 同一帧完成，在第一帧绘制之前就结束了。

所以渐隐动画**一直在正常播放**，只是播在一个 0×0 的盒子里 —— 这是**布局阶段**的裁剪，与动画时间轴无关。
这解释了此前所有「动画侧」的尝试（拆两段、同步 `ease`、`ease-in`）为何全部无效：方向错了。

**判据（决定性、30 秒）**

内容撑出滚动条时必现；消息不足一屏（free space 非负）时渐隐**正常可见**。
DevTools 里给 `.msg-row` 临时加 `flex-shrink: 0`（或临时取消勾选 `.msg-row.is-leaving` 的 `overflow: hidden`），
再撤回一次 → 渐隐立刻出现。

**处置**

| 处置 | 结果 |
|---|---|
| **`.msg-row` 加 `flex: 0 0 auto`** | ✅ **主修**。退场行不再参与收缩，渐隐播在有高度的盒子里（浏览器确认） |
| 收空间的触发点：transition `delay` → `nextTick` → 双 rAF → **渐隐的 `animationend`** | ✅ 相位边界由动画自己的时间轴给出。`nextTick` 只是微任务、不保证已排版；双 rAF 能保证，却把收空间推迟 1~2 帧、越过 `LEAVE_MS` 的移除时刻，末尾被截断成一次跳动 |
| `height` 与 `margin-top` 合并为**一次**行内写入（`leaveStyle`） | ✅ 修掉「margin-top 跟着 class 在 t0 就动、height 等到阶段 2 才动」的脱节（表现为先把两行各上提 16px 的「卡一下」） |
| 分段 60/40 → **50/50**，渐隐 `ease` + 收空间 `ease-in-out` | ✅ 消掉「淡完到起收」的空档：`ease` 前段快，120ms 的渐隐约 100ms 就淡透；`ease-in-out` 起步慢，120ms 起手时几乎还没动 |
| `LEAVE_MS` 300 → **240** | ✅ 节奏更快；总时长与上游移除定时器同源，仍是「动画播完 = 从队列移除」 |
| 用 `min-height: 0` 之类的「反向修法」 | ❌ 不可用：那正是把保护彻底拆掉，症状只会更稳定地复现 |

**关键点**

- **给 flex 项加 `overflow: hidden` 做动画裁剪是有代价的**：它会顺手消掉自动最小尺寸。若该行处在「内容超高的滚动 flex 列」里，
  就会被压成 0 高。要裁剪，就同时 `flex: 0 0 auto`（或显式给 `min-height`）。
- `height: auto` 不能参与过渡，必须先量成 px；量出来的值还必须是**已提交**的样式变更起点，后面的 0 才有插值区间。
  三种等待的差别：`nextTick` 不保证排版；双 rAF 保证但引入 1~2 帧延迟；`animationend` 既保证又不引入延迟。
- 拆两段时，**前段 `ease` + 后段 `ease-in-out`**：两段都用 `ease` 会在中段露出空档（前段提前淡透，后段一上来就吃掉近一半高度）。
- 同一时刻要动的两条几何属性必须**同一次写入**，否则会脱节成两段动作。

**验证状态**

主修与 `animationend` 触发经浏览器确认（渐隐可见、两段连续）；50/50 与 240ms 为最终采纳的节奏，未再逐帧核对。

**相关位置**

- `src/components/Chat/MessageRow.vue`：`.msg-row` 的 `flex: 0 0 auto`；`.msg-row.is-leaving` 的两段动画与过渡；
  `leaveStyle`、`onLeaveFadeEnd`（模板根的 `@animationend`）
- `src/components/Chat/ChatBoard.vue`：`LEAVE_MS`（退场时长 + 移除定时器同源）、`--leave-ms` 经 `.chat-board-content` 继承给 MessageRow
- 证据：构建产物里 `.msg-row` 无 `flex` 声明（默认 `flex: 0 1 auto` → `flex-shrink: 1`），
  而 `.chat-board-content` 为 `flex: 1 + overflow-y: auto + flex-direction: column`

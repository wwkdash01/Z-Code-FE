# 亚像素跳变排查（1px 级跳变）

> **来源**：wwk_frontend 项目 2026-09-13 的两次实际排查（输入区小图标静止偏右、应用详情弹层动画播完下移）。
> **用途**：本文件是**可整份拷贝的排查手册**，新前端项目直接放进 `docs/` 即可用，不依赖本项目任何代码。
> **适用现象**（命中任一条就来查）：
> - 元素**静止时**偏半个像素，悬停/点击**动画播放期间反而对齐**，动画一结束又偏回去
> - **动画播完的瞬间**元素突然跳 1px（往上或往下、往左或往右）
> - 弹层/浮层"出现的位置"与"落定的位置"差 1px
> - 加了 `will-change: transform` 就好了，但你不确定它靠不靠得住

---

## 一、先判族：一个 30 秒的判定

给**嫌疑元素**在 devtools 里临时加一条内联样式（别动代码）：

```css
will-change: transform;
```

| 加完之后 | 属于哪族 | 一句话根因 |
|---|---|---|
| 现象**消失** | **光栅化族** | 元素的**布局位置没变**，但"在自己那层里绘制"与"在父层里绘制"两条路径的取整不同 |
| 现象**仍在** | **时序族** | 元素的定位值**真的变了**——某个事件（多是动画结束）触发了一次重新定位或重算 |

这个判据之所以有效：光栅化族的病根就是"元素平时不在合成层上"，`will-change` 恰好把它常驻上去了，所以症状会消失；
时序族的位置是真被改写的，跟在哪一层绘制无关，`will-change` 自然无效。

### ⚠️ 反例警示（本项目踩过）

**"关掉修法 A 后问题还在"不能否定 A。** A 可能只是一部分原因，也可能 A 压根没生效。
本项目就犯过这个错：查到两条"重新对齐"的路径都不触发，就下结论「已排除重新定位」，进而把整族判成光栅化族，
白改了一轮 `will-change`。真相是那两条之外还有第三条（见第三节）。
**排除法必须穷举；穷举不到就写"未验证"，不要写"已排除"。**

## 二、光栅化族

### 机制

元素靠 `transform` 做动画时，会被提升为**独立合成层**——但**只在动画播放期间**。
动画一结束，层被回收，元素回到父层，改由父层的绘制原点取整。
两份取整结果在"位置或盒子尺寸是小数"时差约半个像素，于是表现为：

- 动画期间 → 在层内取整 → **对齐**
- 动画结束 → 回父层取整 → **偏**

### 触发条件（两条同时成立才发病）

1. 元素的布局位置或盒子尺寸是**小数**（例如图标盒由 `font-size: 10.5px` 撑出来）
2. 元素**只在动画期间**是合成层（靠 `transform` 动画被动建层）

### 修法：把"提示"换成"真值"，并连关键帧一起改

```css
/* ① 基础值用真值 3D 变换：浏览器必须建层。
      will-change 只是提示，内存吃紧时可被撤掉 —— 这就是它"有效但不敢依赖"的原因 */
.icon {
  transform: translate3d(0, 0, 0);
}

/* ② 所有相关关键帧的首尾帧也必须带 3D */
@keyframes tap {
  0%   { transform: translate3d(0, 0, 0); }
  45%  { transform: translate3d(0, -2px, 0) rotate(9deg); }
  100% { transform: translate3d(0, 0, 0); }
}
```

**最容易漏的是 ②。** 只改基础值没用：首尾帧写 `transform: none` 会在动画开始/结束那两帧把层丢掉，
偏移就恰好在"点下去那一瞬"回来。这跟原症状"动画期间正常"容易被混为一谈，实际是同一病因的另一半。

同时检查 `:hover`、`:active`、`:disabled` 等**所有覆盖 `transform` 的规则**，一律换成 3D 写法
（`translateY(y)` → `translate3d(0, y, 0)`），否则悬停/按下期间层被降级，偏移在那段时间回来。

### 已验证无效的路子（别重复试）

| 试过 | 结果 |
|---|---|
| 换图标（换一个 glyph） | ❌ 现象不变 |
| 形状从正圆改圆角矩形 | ❌ 无改善 |
| 静态亚像素补偿（`left: -0.5px` / `-1px`） | ❌ 两端都过头，而 0 又偏右侧 → 静态路径的落点是**离散**的，不存在可用的补偿值 |
| 把父容器尺寸用 `round()` 取整成整像素 | ➖ 与该症状无关（病根在绘制取整，不在布局小数；且原"判定它无效"的依据本身不成立） |

## 三、时序族

### 机制

动画结束会触发状态切换，而 UI 库的状态机在切状态时**可能顺手重算一次位置**。
如果此时**被用作定位参照的元素自身几何正在变**，重算结果就与第一次不同 → 症状是"动画播完跳一下"。

### 实例：antd 弹层（本项目实测）

链条（每一步都在 `ant-design-vue` 源码里核对过）：

1. 弹层用 `left/top` 布局属性定位（不是 `transform`），对齐用的是**触发器元素**的 rect
2. 开启过程只对齐一次：`status === 'align'` 时放行对齐，进入 `'motion'` 后**把对齐关掉**
3. 入场动画播完 → `onAfterEnter` 里强制 `status = 'stable'`
4. `'stable'` 又让对齐**放行** → `disabled` prop 翻转 → `forceAlign()` → **第二次对齐**
5. 而当时把「按下缩放」`transform: scale(.92)` + 150ms 过渡挂在了**触发器**上，触发器正是定位锚点：
   第一次对齐时它还在回弹途中（≈0.93），第二次对齐时已回到 ≈0.97，底边差 ≈0.9px → 弹层跟着下移 ≈1px

**注意第 3 步的时序**：入场动画只有 0.1s，而回弹过渡是 0.15s——动画先结束、回弹还没走完，
所以跳变必然精确发生在动画结束那一刻。**"现象精准卡在动画结束"本身就是时序族的强信号。**

### 修法：让锚点几何恒定，要动的效果挪到它内部

```html
<!-- 锚点：静态，不被任何动画改变几何 -->
<span class="anchor">
  <!-- 效果作用在内层。transform 不改变布局盒，所以外层 rect 恒定 -->
  <button class="press-scale">…</button>
</span>
```

一句话原则：**任何被用作定位锚点的盒子，都不要在它身上挂会改几何的效果。**

### 定位手法：两侧同时打点

只在值变化时打印，一次就能分清"谁在动"：

```js
(() => {
  let prev = ''
  const tick = setInterval(() => {
    const anchor = document.querySelector('.anchor')   // 定位参照元素
    const target = document.querySelector('.popup')    // 表现为跳变的元素
    if (!anchor || !target) return
    const r = anchor.getBoundingClientRect()
    const cs = getComputedStyle(target)
    const line = `anchor.top=${r.top.toFixed(3)} anchor.h=${r.height.toFixed(3)}`
      + ` | target.inlineTop=${target.style.top} transform=${cs.transform} anim=${cs.animationName}`
    if (line !== prev) { prev = line; console.log(line) }
  }, 16)
  setTimeout(() => clearInterval(tick), 4000)
})()
```

触发一次现象，然后读输出：

| 观察到 | 结论 |
|---|---|
| `target.inlineTop`（或 `left`）**变了** | **时序族**：确实被重新定位了 |
| `anchor.*` **变了** | 找到了根源：锚点在动 → 让锚点几何恒定 |
| 两者都**没变**，但观感仍变 | 回到光栅化族，走第二节 |

## 四、可复用的规范（建议写进新项目的前端约定）

1. **带时序的现象先怀疑事件时序**：`animationend` / `transitionend` → 状态机切换 → 副作用。
   渲染层的问题通常**不会精准卡在动画结束那一帧**，所以"精准卡在动画结束"是把范围缩到逻辑层的强信号。
2. **排除法必须穷举**，不能用"我想到的两条路径不触发"去否定整类。写结论时严格区分「已验证不触发」与「已排除」。
3. **锚点几何恒定**：任何被用作定位参照的盒子，不要在它身上挂改几何的动画/效果；要动就动它内部。
4. **`will-change` 是提示不是承诺**。需要确定性建层时，用真值 3D 变换（`translate3d(0,0,0)`），
   并让关键帧与各状态下的 `transform` 全程保持 3D。
5. **先在 devtools 内联样式里验证假设，再动代码**。本项目两次排查各栽过一次"没先验就盲改"：
   一次是盲改 `will-change`（无效），一次是用"关掉修法 A"去否定 A。

# 用户管理页样式重构方案

> 目标：把「用户管理」（`/admin/user-manager`）的详情/编辑流程与视觉标准，对齐到刚完成的「应用管理」（`/admin/app-manager`）。
> 本文档为审阅稿，**批准后再执行**。

---

## 一、现状盘点

### 1.1 当前实现

| 关注点 | 用户管理（现在） | 应用管理（标准） |
|---|---|---|
| 入口 | 操作列「编辑」+ 「更多」列「详情」**两个按钮** | 操作列**一个**「详情/修改」 |
| 弹窗 | `UserInfoEditCard`（编辑，整表单 + 保存按钮）<br>`UserInfoDetailCard`（详情，`a-descriptions` 只读）**两个弹窗** | 单弹窗 `AppInfoDetailEditCard` |
| 数据来源 | 直接用**表格行数据**，不重新拉详情 | 打开时按 id 调 `getAppByAdmin` 拉全量详情 |
| 提交时机 | 编辑弹窗底部「保存」按钮，**一次性提交全部字段** | 弹窗「确定/OK」按钮，**只提交变化字段** |
| 保存反馈 | 成功 → 关弹窗 + `message` | 成功 → 先关闭卡片再 `message`，失败 → **重置卡片** + `message` |
| 可编辑控件 | 有边框的 `a-input`（`userName` 等） | **无边框** `:bordered="false"`，hover 有浅色底提示可编辑 |
| 空值占位 | 直接渲染 → 空白单元格/空白字段 | 表格 `/`，弹窗 `无`（统一 `display()` 出口） |
| 表格对齐 | 默认左对齐 | 表头 + 表体**全列居中** |
| 标签样式 | 角色 tag 绿色/蓝色，硬编码在页面里 | 标签走 `@/config/appTag` 单一数据源 |

### 1.2 现有文件

```
src/pages/admin/UserManagePage.vue        236 行，页面 + 两个弹窗的接线
src/pages/admin/UserInfoEditCard.vue      274 行，编辑弹窗
src/pages/admin/UserInfoDetailCard.vue    148 行，详情弹窗
```

### 1.3 后端能力（已核实）

`PUT /api/users/admin/{id}` → `UserUpdateRequestDTO`，可改字段**仅 6 个**：

| 字段 | 校验 | 说明 |
|---|---|---|
| `userAccount` | 6–32 位 | 账号 |
| `userPassword` | 6–24 位 | 非空则后端**加密后覆盖**；不传则不动 |
| `userName` | ≤256 | 昵称 |
| `userAvatar` | ≤1024 | 头像 URL |
| `userProfile` | ≤512 | 简介 |
| `userRole` | ≤256 | `user` / `admin` |

`GET /api/users/admin/{id}` 返回 **User 实体**（未脱敏），因此弹窗可以拿到 `vipExpireTime` / `vipCode` / `vipId` / `shareCode` / `inviteUser` / `editTime` 等只读字段。

> ⚠️ VIP 相关字段只存在于 `UserAddRequestDTO`，**`UserUpdateRequestDTO` 里没有**，因此弹窗中这些字段只能只读展示，不能编辑。

服务层语义与 app 一致：`BeanUtils.copyProperties` + `updateById`（MyBatis-Flex 默认 `ignoreNulls=true`），**未传字段不会被清空**（已在应用管理那轮实测验证）。

## 二、目标设计

### 2.1 入口与操作列

```
操作列：  详情/修改  |  删除
```

- 删掉「更多」列（`dataIndex: 'info'`）与「详情」按钮 —— 与 app 一致
- 删掉操作列里独立的「编辑」按钮
- 保留 `a-popconfirm` 的删除

### 2.2 单弹窗 `UserInfoDetailEditCard.vue`

拆掉 `UserInfoEditCard.vue` + `UserInfoDetailCard.vue`，新建**一个**组件，沿用 app 的组件契约：

```ts
defineProps<{ open: boolean; userId?: string | number }>()
defineEmits<{ 'update:open': [boolean]; success: [] }>()
```

- 页面只传 `userId`，**组件内部按 id 拉全量详情**（现在是拿行数据，缺少 vip 等字段）
- 打开时 `origin = null` → 拉取 → 回填草稿（`resetDraft()`）

### 2.3 弹窗内部布局

保持现有「左头像 + 右字段」的双栏结构（用户管理比应用管理多一个可改头像，这栏值得留），但字段区改成 app 的**字段网格**风格：

```
┌──────────────┬──────────────────────────────────────────┐
│              │  昵称[a-input 无边框]   账号[a-input 无边框]│
│   [头像]      │  简介[a-input 无边框 跨行]                 │
│  （点击提示    │  角色[a-select 无边框]   密码[a-input 无边框]│
│    mock 上传） │  头像URL[a-input 无边框 跨行]              │
│              ├──────────────────────────────────────────┤
│  昵称（大字）  │  id        无      VIP到期时间   无        │
│  角色 tag     │  VIP编码   无      VIP ID       无        │
│              │  分享码    无      邀请人        无        │
│              │  编辑时间  无      创建时间      无        │
│              │  更新时间  无                            │
└──────────────┴──────────────────────────────────────────┘
```

- **可编辑字段**（6 个，全部无边框）：昵称、账号、简介、角色、密码、头像 URL
- **只读字段**：id、VIP 到期时间、VIP 编码、VIP ID、分享码、邀请人、编辑/创建/更新时间
- 只读字段用灰色文本样式（复用 app 的 `.field-text--readonly` 口径）
- 空值统一走 `display()` → 弹窗内显示 **`无`**

### 2.4 密码字段的处理（需要你确认）

- 输入框 `placeholder="不修改则留空"`，`type="password"`
- 草稿里初始为空。**只在非空且与原值不同时**才提交 `userPassword`
- 长度校验 6–24 位，不满足则 `message.warning` 阻止提交
- 这是唯一一个「提交后前端拿不到回显」的字段（后端存的是加密值），因此**失败重置时清空该输入框**

### 2.5 头像字段的处理

- 左侧头像点击：保留现有 mock 行为（`message.info('模拟头像变更')`），不接真实上传
- 右侧新增**「头像 URL」可编辑输入框**，改完点「确定」真实落库（`userAvatar`）

### 2.6 提交与反馈（严格对齐 app）

```
点「确定」
  ├─ 校验：账号 6–32 / 昵称非空 / 密码非空则 6–24 / 角色合法
  ├─ 汇总变化字段 → body 只装变化项
  ├─ body 为空 → 直接关闭，不发请求
  ├─ 成功 → 关闭卡片 → message.success('保存成功') → emit('success') 刷新列表
  └─ 失败 → resetDraft() 重置卡片 → message.error('保存失败：…')
```

- 弹窗接 `@ok` / `:confirm-loading="saving"` / `ok-text="保存"` / `cancel-text="取消"`
- 保存中所有可编辑控件 `:disabled="saving"`

### 2.7 表格对齐与空值（对齐 app）

| 项 | 做法 |
|---|---|
| 全列居中 | `class="admin-table--center"` + `:deep(.ant-table-thead > tr > th)` / `:deep(.ant-table-tbody > tr > td)` 居中；列定义补 `align: 'center'` |
| 空值 | 新增 `EMPTY_TEXT = '/'` + `display()`，覆盖账号、昵称、简介等列 |
| 角色列 | tag 保留（`user` 绿 / `admin` 蓝），但抽成常量，不再写死在模板里 |

> 应用管理那边的「应用名称 10em 截断 + 渐隐」是应用名特有的需求，**用户管理不套用**（昵称列暂无截断需求，如需可后续单开）。

## 八、追加需求：用户名渐变截断（已完成）

### 做法：把应用名称那套逻辑抽成共享实现，两处复用

原先「固定宽度 + 超出才渐隐」的三处逻辑（CSS / 判定 / ResizeObserver）都硬写死在 `AppManagePage.vue` 里。为了不在用户管理里复制一遍，先抽出来：

| 新增文件 | 内容 |
|---|---|
| `src/composables/useNameTruncation.ts` | 判定逻辑：`boxStyle`（10em 盒子宽度）/ `overflowIds`（溢出集合）/ `setCellRef` / ResizeObserver |
| `src/styles/base.css` 追加 `.name-cell` 系列 | 布局与视觉：固定宽度盒子、居中溢出文字、只在 `--overflow` 时挂渐隐遮罩 |

`AppManagePage.vue` 改为调用该 composable（删掉 `APP_NAME_MAX_EM` / `APP_NAME_BOX_STYLE` / 手写判定与 observer 共约 40 行），`UserManagePage.vue` 的用户名列用同一套。

### 验证（用真实 base.css + 真实判定逻辑跑的无头 Chromium 探针）

| 文本 | 盒宽 | 文字自然宽 | 渐隐 |
|---|---|---|---|
| `sksa` | 140px | 29px | 否 |
| `qwen38重构` | 140px | 80px | 否 |
| `测试5hihihi` | 140px | 71px | 否 |
| `dsf41测试asdads` | 140px | 109px | 否 |
| `wwkapptestapplalal` | 140px | 127px | 否 |

与 4.1 节记录的应用名称口径完全一致：**≤140px 一律全实心，>140px 才渐隐**，不会误伤短名字。

> 注：用户管理里超长昵称正是自动生成的「默认用户名 + UUID」格式，恰好命中截断分支；此前表格行高 57px 的成因就是这类昵称换行，现在被固定高度 + 裁切一并解决。

## 九、追加需求二：账号列截断 + 角色改为下拉 tag（已完成）

### 9.1 账号列同样加渐变截断

`useNameTruncation` 原先一个实例只支持一列（内部 `Map<id, el>`）。用户名与账号都要截断后，改成按 **`列标识 + id`** 分别记录：

```ts
// composable 新契约
setCellRef(field: string, id, el)          // 登记单元格
isOverflowing(field: string, id)           // 该格是否需要渐隐
```

`UserManagePage.vue` 的账号列与用户名列各用自己的 field（`'userAccount'` / `'userName'`）调同一个实例；`AppManagePage.vue` 传 `'appName'`。一张表多列截断不再需要多个实例。

### 9.2 角色不再在昵称下重复展示，改为下拉里的 tag

- **删除**弹窗左栏昵称下方的角色 tag（`roleMeta` 计算属性一并移除）—— 角色在右栏下拉里已经能看能改，左栏再挂一个是重复信息
- 右栏「角色」下拉改为 **tag 渲染**，做法与应用编辑页的标签下拉完全一致：

```vue
<a-select v-model:value="draft.userRole" :bordered="false" :options="USER_ROLE_OPTIONS">
  <template #option="{ value }"><UserRoleOption :value="value" /></template>
  <template #optionLabel="{ value }"><UserRoleOption v-if="value !== undefined" :value="value" /></template>
</a-select>
```

- **新增** `src/components/admin/UserRoleOption.vue`（13 行，与 `AppTagOption.vue` 同构）：从 `@/config/userRole` 取 `label` / `color` 渲染 tag
- 选中值内部仍是原始枚举字符串，保存 payload 不变
- 两个插槽的分工同应用编辑页：`#option` 管下拉列表项，`#optionLabel` 管单选选中值回显（**单选不走 `tagRender`**，这点已在应用管理那轮查过 antd 4.2.6 源码确认）
